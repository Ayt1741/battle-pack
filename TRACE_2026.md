# Trace — «компиляция правил в проверки» (ход 57, проверено чтением первоисточника)

**Источник:** Zhou и др., «Getting Better at Working With You: Compiling User Corrections into Runtime Enforcement for Coding Agents», arXiv:2606.13174v1 (11.06.2026), Notre Dame + Tencent AI Lab + IBM Research.
Код: https://github.com/YujunZhou/TRACE_exp , https://github.com/YujunZhou/tellonce
Прочитано 22.11.2026, фрагменты 0–3 статьи (аннотация, разделы 1–5).

## Что доказывает статья (цитаты)

1. **Разрыв «доступ ≠ соблюдение».** «Mem0 memory still leaves 57.5 % of applicable preference checks violated» — даже когда коррекция пользователя сохранена в памяти и доступна, 57,5 % применимых проверок нарушаются.
2. **Trace преобразует коррекции в проверки.** «converts user corrections into a growing per-user library of runtime-enforceable rules» — из коррекций строится библиотека атомарных правил, у каждого: applicability check (когда правило действует), behavior instruction (что делать), verifier (как проверить).
3. **Результаты на ClawArena (задачи кодового агента):** нарушения снижены с **100,0 %** до **37,6 %** (в своей области, in-distribution) и до **2,0 %** (вне области, out-of-distribution).
4. **На MemoryArena:** с 100,0 % до 60,5 %; качество выполнения задач не хуже лучшей памяти.
5. **Механизм применения — ХУКИ.** «Hooks serve as the control points that trigger these verifiers at prompt, tool-use, file-write, or termination events. If a verifier fails, the hook interrupts the event and provides the violation details to the agent for immediate correction.» — проверка привязана к событию платформы и БЛОКИРУЕТ событие.
6. **Жизненный цикл правила (5 действий):** Noop (доказательства к существующему правилу), Update (уточнение), Supersede (отмена старого при конфликте), Split (разделение сложного), New (новое).
7. **Ограничение:** ретраев не больше трёх на задачу, дальше запуск завершается с записанным нарушением.

## Почему у нас это не сработает «как есть»

У Arena Agent Mode нет событий prompt/tool-use/file-write/termination, к которым можно прицепить verifier. Значит нужна замена хукам — привязка проверки не к событию платформы, а к ФОРМЕ ОТВЕТА и к файлу-квитанции: ответ без пройденной проверки неполон по определению (нет обязательного поля).

## Вывод хода 57

Главное — не «ещё одна проверка», а **таблица «правило → машинная проверка → что делать при провале»**, собранная из 108 пунктов законов. Из них машинно проверить можно далеко не все; задача «мозга» (Battle) — пройти по списку и сказать, какие правила сводятся к проверке, а какие нужно переформулировать, чтобы сводились.
