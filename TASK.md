# ЗАДАНИЕ «МОЗГУ» (Battle Code) — ход 55

Ты — «мозг» проекта «Кухня»: топ-модель, которой поручено продумывание, тактика и код. Агент-исполнитель (ИИ в режиме Arena Agent) только собирает и
запускает. Заказчик (пишет по-русски, не программист) требует: ответ без воды, с числами, проверяемый командой.

## Материалы (скачай и прочитай ВСЕ файлы — это обязательное условие, ответ без этого не принимается)
Все файлы — обычный текст UTF-8 по ссылкам из INDEX.md (там же порядок чтения):
LAWS.md (законы заказчика, ≈100 пунктов) · HANDOFF.md (состояние, решения, частые претензии) · CONTRACT.md (что уже построено против нарушений) ·
CORE.md (короткое ядро законов) · LESSONS.md (уроки) · FACTS.md (проверенные факты) · USER_COMPLAINTS.md (100 последних запросов заказчика) · TOOLS.md (инструменты).

## Проблема (главная боль заказчика)
ИИ-агент не выполняет законы заказчика и забывает сказанное — в КАЖДОМ ходе, несмотря на файл законов, журнал, гейт и контракт из 16 пунктов (см. CONTRACT.md).
Заказчик пишет: «ты снова нарушил», «где 100 запросов», «ты не руководишь», «лезешь проверять то, что я уже сказал», «выдумываешь числа».

## Условия среды (жёсткие)
1. Агент работает в Arena Agent Mode: контекст периодически сжимается в краткую сводку; процессы не живут между запросами; живут только файлы рабочей папки
   (лимит снимка ≈128 МБ) и внешняя память (приватный Telegram-канал). Хуков уровня Claude Code нет; системный промт менять нельзя.
2. Только бесплатное, только стандартная библиотека Python, без платных API. Нельзя автоматизировать сторонние сервисы против их условий.
3. Заказчик не программист: ничего ручного «кликни там-то», кроме одного короткого слова-команды в чате.

## Что нужно (по пунктам, по-русски, с числами)
1. **Причины.** Почему при наличии файла законов и гейта агент всё равно нарушает? Опирайся на USER_COMPLAINTS.md: для каждой из 8 повторяющихся претензий — 1 цитата с номером
   и 1 механизм, почему она повторяется.
2. **Не больше 10 мер.** Для каждой: механизм → чем проверяется машиной (команда + ожидаемый вывод) → какая претензия закрывается. Учти условия среды.
3. **Код.** Для 3 самых важных мер — рабочий код на Python (stdlib), с запуском и ожидаемым выводом. Не переписывай то, что уже есть в TOOLS.md, — дополняй и указывай, какой файл править.
4. **Тест-набор.** 20 сценариев «запрос заказчика → поведение, которое считается нарушением / соблюдением» на основе реальных претензий; формат — таблица.
5. **Порядок внедрения** на 3 ближайших хода: что делать в первом, втором, третьем.
6. **Честно:** что в этих условиях невозможно гарантировать и чем это компенсировать.

## Поиск (закон заказчика: сначала интернет, готовое лучше своего)
У тебя в этом режиме есть интернет. Найди готовые решения (открытые проекты, статьи): постоянные правила для LLM-агентов, проверка соблюдения инструкций,
память агентов между сессиями. Сделай не меньше 30 РАЗНЫХ поисковых запросов, перечисли их списком в конце и укажи, что из найденного взято.

## Формат ответа
Без вступлений. Заголовки 1–6 как выше. В конце: список поисковых запросов. Каждое утверждение — цифра с источником или действие с проверкой.
В первой строке ответа напиши свою модель и её место в рейтинге Arena, если знаешь.
