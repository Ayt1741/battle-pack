# ЗАДАНИЕ «МОЗГУ» (Battle Code) — ход 55, версия 2 (роли исправлены заказчиком)

## Роли (прочти первыми)
- **Совет из 40 агентов** (10 руководителей + 30 исполнителей) — СБОРЩИКИ. По протоколу заказчика (этап 0 — план; этап 1 — батчи с разбором и запросами «по ходу»; этап 4 — отчёт) они искали информацию и собрали материалы: файлы COUNCIL_*.
- **Агент-исполнитель** (ИИ в Arena Agent Mode) — запускает команды в рабочей папке; пока ждал совет, сделал независимый поиск по тому же протоколу: файлы MY_*.
- **ТЫ — «мозг»**: думаешь, пишешь код и ПРОВЕРЯЕШЬ то, что собрали агенты. Агентам на слово верить нельзя: у совета все 10 вердиктов вышли «подтверждено» с весом около 0,85 — подозрительная однородность; рейтинг голосования между двумя запусками совета разный (запуск 1: «Persistent Memory Layers»; запуск 2: «Свежий диалог с передачей состояния»), поэтому рейтингу доверять нельзя — смотри доказательства.

## Проблема (главная боль заказчика)
ИИ-агент заказчика не выполняет его законы и забывает сказанное — в КАЖДОМ ходе, несмотря на файл законов (108 пунктов), журнал, гейт и контракт из 16 пунктов. Заказчик пишет по-русски, не программист, требует: ответ без воды, с числами, проверяемый командой.

## Условия среды (жёсткие)
1. Агент в Arena Agent Mode: контекст периодически сжимается платформой в краткую сводку; живут только файлы рабочей папки и приватный Telegram-канал; хуков нет; системный промт менять нельзя; агент не видит число токенов своего контекста; новый диалог открывает только заказчик (вставляя одно сообщение).
2. Только бесплатное, только стандартная библиотека Python. Нельзя автоматизировать сторонние сервисы против их условий.
3. Заказчик не кликает и не вводит коды; допустима одна вставка короткой строки.

## Что уже найдено (с источниками; проверь, а не принимай)
1. Сводки сохраняют в среднем 17 % ограничений пользователя; если ограничение добавить ПОСЛЕ сжатия, соблюдение 31,8 % → 99,7 % — https://arxiv.org/html/2608.11242v1
2. Теряются правила ПОВЕДЕНИЯ («как действовать»), правила про результат восстанавливаются из файлов; потери копятся от сжатия к сжатию — https://arxiv.org/html/2610.31778
3. Arena: сжатие встроено в Agent Mode; переноса контекста между диалогами нет; модель в сессии может смениться — https://help.arena.ai/articles/3975292349-arena-troubleshooting-session-token-limits , https://help.arena.ai/articles/5432423882-how-to-use-agent-mode
4. Автосообщение «продолжай без вопросов» после сжатия перебивает правила пользователя — https://github.com/anthropics/claude-code/issues/24906
5. Модели-судьи плохо ловят ложное «готово» (AUROC ≤ 0,65), лёгкие детекторы — 0,83–0,95 — https://arxiv.org/abs/2606.09863
6. Напоминания между вызовами инструментов повышают обнаружение (на длине 800K: 99,7 % → 69 % без них) — https://arxiv.org/html/2605.12366v1
7. Запреты читаются как разрешения (77–100 % у открытых моделей), рекомендация Anthropic — формулировать как действие — https://arxiv.org/abs/2601.21433 , https://claude.com/blog/best-practices-for-prompt-engineering
8. Длина файла правил 25→500 строк на выполнение одного правила не влияет — https://arxiv.org/pdf/2605.10039 (это противоречит советам «урезать законы»).

## Что нужно от тебя (по порядку; по-русски, с числами)
1. **ПРОВЕРКА (до выводов).** Открой ссылки и проверь не меньше 10 цитат: по 5 из COUNCIL_FINDINGS.md и MY_FINDINGS.md. Таблица: № | файл | начало цитаты | ссылка | цитата на странице есть (да/нет) | подтверждает вывод (да/нет). Отдельно перечисли неподтверждённые или неверные утверждения, в том числе в COUNCIL_REPORT.md: часть его советов нарушает условия среды (подмена системного промта, подсчёт токенов через len(split)).
2. **ПРОТИВОРЕЧИЯ.** Между советом и MY_*, а также внутри самих материалов (пример: «ограничить объём правил» против пункта 8). Закрой каждое цитатой.
3. **РЕШЕНИЕ.** Не больше 10 мер. Для каждой: механизм → источник → чем проверяется машиной (команда + ожидаемый вывод) → какую претензию заказчика закрывает → выполнимо ли в Arena Agent Mode без хуков (да/нет и почему). Кандидаты из материалов (не обязательные, оцени, отбрось лишнее, добавь своё): M1 правила ядра возвращаются в конец контекста первым действием хода и перед отправкой; M2 строка-напоминание в выводе панель/действие.py после КАЖДОГО действия; M3 детерминированная проверка ответа вместо модели-судьи; M4 правило «после сводки и слова „продолжай“ первым действием читаю ядро» с проверкой гейтом по журналу панели; M5 положительные формулировки + детекторы запретов; M6 чистка дублей и противоречий законов; M7 свежий диалог + СТАРТ-ПРОМТ; M8 реестр пунктов запроса со статусом pass/fail.
4. **КОД.** Рабочий Python (stdlib) для 3–4 главных мер, с запуском и ожидаемым выводом; укажи, какой файл править (TOOLS.md перечисляет инструменты; CHECKER.py — текущая проверка ответа; дополняй, а не переписывай).
5. **ТЕСТЫ (этап 3 протокола заказчика).** Фикстура, воспроизводящая ИМЕННО найденную причину: сводка теряет правила поведения; автосообщение «продолжай» перебивает правила. Замер «до» и «после» в цифрах на 20 сценариях; старая версия должна «ломаться» на фикстуре, иначе фикстура не годится.
6. **ПОРЯДОК ВНЕДРЕНИЯ** на 3 ближайших хода.
7. **ЧЕСТНО.** Что в этих условиях нельзя гарантировать; что делать, если не заработало (какой лог или вывод нужен от заказчика).
