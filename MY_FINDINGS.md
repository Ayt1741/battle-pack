Вердикт: подтверждено (4 источника, один приём: список ограничений дословно, отдельным полем).

**H1 · как сжимают другие** — OpenAI: «All prior user messages are kept verbatim. ## Батч H1-B (по ходу, после H1-A; запросы N1–N4, придуманы по ходу)

**H1 · первоисточник (arXiv 2608.11242, Penn State + IBM)** — «In an inbox experiment, an agent deleted emails without approval in 30/100 sessions after compaction, compared with none before compaction»; «On these natural trajectories, no evaluated compactor retains more than 28.6% of SCs»; «Current compactors retain only 17% of injected SCs on average, and most perform worse than running the same task without compaction»; в агентной обвязке: «Compliance is 31.8% when the model receives the compacted context alone, but reaches 99.7% when the SC is appended after compaction»; место правила: «later injection locations yield higher retention rates» — https://arxiv.org/html/2608.11242v1 и https://arxiv.org/pdf/2608.11242 . Вердикт: ПОДТВЕРЖДЕНО первоисточником. Главный вывод для нас: правила, поставленные ПОСЛЕ сжатия, в самый конец контекста, соблюдаются в 99,7 % случаев (31,8 % без этого).

**H1 · контр-данные (не все сводки одинаково плохи)** — «From 44 sampled SWE-chat sessions (which used Claude Code…) they extracted 269 user constraints and checked each against the next compaction summary. Overall 81% were preserved and 19% dropped»; но «the first summary omits on average 0.92 of the three categories, and by the tenth compaction the average is 1.93. Later summaries inherit earlier omissions, so the loss compounds» — https://www.alphaxiv.org/abs/2610.31778 . Вердикт: подтверждено с оговоркой: у сильных сводчиков потери меньше (19 % против 83 %), но они копятся от сжатия к сжатию; наш диалог сжимался много раз.

**H1 · есть ли выигрыш от «реестра ограничений» в сводке** — открытая реализация: список ограничений дописывается к сводке («the registry is appended to the compaction summary») — https://arxiv.org/html/2608.11242v1 (Appendix J); контр-пример: в одном проекте реестр дал «32/32 in both arms, so the ledger gave no recall gain» и выключен по умолчанию — https://github.com/telemusai/optimus-agent/pull/179 ; структурная сводка с разделом «Constraints and preferences» — https://github.com/use-agent-os/agent-os/pull/3724 . Вердикт: неясно (зависит от сводчика; в синтетике помогает до >90 %, в другом тесте разницы нет).

**H1/H2 · как держат правила другие агенты** — Codex: «keeps your recent messages word for word, up to 20,000 tokens, walking newest to oldest. It adds a summary and re-injects its starting context» — https://dev.to/theaicommit/how-to-tell-what-claude-code-and-codex-forget-when-they-compact-a-session-532a ; Anthropic: «Your requests and key code snippets are preserved, and detailed instructions from early in the conversation may be lost» — https://dosu.dev/articles/context-compaction-coding-agents . Вердикт: подтверждено.

**H8 · блог Arena про устройство сжатия** — найдена только справка с одной фразой («compressed into a summary»); подробностей про сохранение реплик пользователя нет. Вердикт: НЕ НАЙДЕНО (запрос N4 закрыт без результата; вывод: что сохраняет сводка Arena, можно проверить только на себе).

## Батч H5-A (самопроверка и внешняя проверка; запросы №47–52 плана + 1 по ходу N5)

**H5 · самопроверка без внешней обратной связи не работает** — «LLMs struggle to self-correct their responses without external feedback, and at times, their performance even degrades after self-correction»; «without the use of oracle labels, self-correction consistently results in a decrease in performance» — https://arxiv.org/abs/2310.01798 (ICLR 2024) и https://arxiv.org/html/2310.01798v2 . Вердикт: ПОДТВЕРЖДЕНО (первоисточник).

**H5 · ложное «готово» и судьи-модели (2026)** — «45–48% of failures in single-control tau2-bench domains … 75.8% among AppWorld self-assessing coding-agent trajectories with explicit status claims»; «no configuration across 5 judges, 5 prompt strategies … exceeds AUROC 0.65 on tau2-bench»; «Lightweight TF-IDF detectors achieve task-disjoint AUROC 0.83 on tau2-bench and 0.95 on AppWorld … 4–8x more false successes than the best judge … with 3,300x lower latency»; вывод авторов: «production monitoring should use lightweight, domain-calibrated detectors as triage signals rather than relying on LLM judges» — https://arxiv.org/abs/2606.09863 . Вердикт: ПОДТВЕРЖДЕНО. Для нас: дешёвая детерминированная проверка (регулярки, счётчики, сверка с журналом) лучше, чем «модель-судья».

**H5 · иллюзорное завершение и реестр ограничений** — «agents conclude the task is complete while a constraint remains unverified in up to 48% of their correct answers»; когда агенту показали состояние каждого ограничения, он отвечает правильно на «4.4-16.1 points» больше — https://arxiv.org/abs/2602.07549 . Вердикт: подтверждено (реестр пунктов запроса и их статусов — рабочий приём; у нас это Я1).

**H5 · принудительная проверка конца хода (образец)** — Stop-хук Claude Code: «Exit code 2 blocks Claude from stopping and forces it to continue working. This single mechanism prevents the agent from saying “done” when it isn’t» — https://shipwithai.io/blog/claude-code-self-verification-loop/ ; рабочий скрипт с `stop_hook_active` — https://joxo.ai/blog/make-claude-code-run-tests-before-done ; тест хука без сессии: `echo '{"stop_hook_active":true}' | .claude/hooks/tests-before-stop.sh; echo $?` — https://agentkitdrawer.com/claude-code-stop-hook-tests/ . Вердикт: подтверждено (код есть), но ТРЕБУЕТ ХУКОВ — в Arena Agent Mode хуков нет → прямо перенести нельзя.

**H5 · квитанции (receipts)** — «Every tool call an agent makes through the gateway becomes a signed record» — https://github.com/svayatta/agent-custody ; «Signed, hash-chained receipts for every tool call and LLM call» — https://github.com/SpowZy/even . Вердикт: подтверждено (два репозитория с рабочим кодом); наш аналог уже есть: панель/действие.py с цепочкой хешей; проверка совпадения номера в ответе — `--сверить`.

**H5 · готовый проверяльщик соблюдения правил по журналу (частично подходит)** — «Check whether your coding agent actually followed its CLAUDE.md / AGENTS.md / .cursorrules. Linters check the file; this checks the behavior … extracts the imperative rules (the prohibitions and the mandates), then scans an agent session transcript for the places the agent broke them» — https://github.com/0xelitesystem/agent-rules . Вердикт: подтверждено как идея и код; встроенные проверки заточены под разработку (bare python, --no-verify, .env), для русских законов заказчика нужны свои правила → у нас это `проверка-ответа.py` + `сверка-ответов.py`.

**H5/H8 · «читал ли агент правила» — та же дыра у других** — «AGENTS.md … only point at .agents/rules.md … Nothing loads it, and nothing checks the agent read it. Hooks are the only enforcement layer today»; варианты: «Session-start advisory nudge» (мягко) и «First-action deny gate. Deny Edit / Write / Bash until a read is observed … Hard guarantee» — https://github.com/cbartens/bkit/issues/700 . Вердикт: подтверждено. Это ровно дефект прежнего «читать журнал первым»: строка «прочитано 100 %» без попадания текста в контекст.

**H5 · «ответ не принят — вернуть модели»** — «a final answer that fails [the check] goes back to the model as a user message, and the loop continues within MaxTurns» — https://github.com/omniaura/agentflow/pull/122 . Вердикт: подтверждено как приём; в Arena финальный ответ перехватить нечем (нет хука) → проверку делает сам агент до отправки.

## Батч H2-A (канал и свежесть; запросы №13, 14, 15, 17, 19 плана) + запрос по ходу N8 (AgentIF, это H3)

**H2 · позиция правила** — «performance is often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts, even for explicitly long-context models» (цитата первоисточника «Lost in the Middle») — https://prompt-architects.com/blog/671-recency-and-primacy-where-to-put-the-important-bit ; практика «instruction sandwich»: ограничение в начале И в конце — https://tianpan.co/blog/2026/04/14/the-instruction-position-problem ; «If a constraint was stated early in a long conversation and the agent appears to have forgotten it, restate it at the end … After context compression, restate the objective explicitly» — https://agentpatterns.ai/context-engineering/lost-in-the-middle/ . Вердикт: подтверждено качественно (первоисточник). Цифра «30–50 %» в блоге tianpan.co без ссылки на исследование → НЕ беру как факт (неясно).

**H2 · пересказ целей в конец контекста (Manus)** — «By constantly rewriting the todo list, Manus is reciting its objectives into the end of the context. This pushes the global plan into the model’s recent attention span, avoiding “lost-in-the-middle” issues» — https://www.ainbox.in/inbox/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus (пересказ блога Manus); оговорка: «Todo recitation keeps the goal at the end of context, but Deep Agents v0.7 evals show it is not a free win» — https://www.marktechpost.com/2026/09/12/context-engineering-inside-the-harness-4-mechanisms-that-beat-context-overflow-and-goal-loss-on-long-horizon-tasks/ . Вердикт: подтверждено, но не бесплатно (смешанные данные).

**H2 · повтор текста** — «repeating the prompts consistently improves model performance for a range of models and benchmarks, when not using reasoning»; «Out of 70 model–task combinations tested, prompt repetition improved performance in 47 of them and never caused a significant drop» — https://arxiv.org/abs/2512.14982 (Google Research; пересказ https://blog.gopenai.com/important-things-should-be-said-twice-or-three-times-a-surprisingly-powerful-prompt-trick-b57d642a1279 ). Вердикт: подтверждено для моделей БЕЗ рассуждений; для моделей с рассуждением эффект меньше → неясно для нашей модели.

**H2 · вес канала «результат инструмента»** — «strong S>U compliance is not a reliable proxy for U>T robustness: several models preserve system constraints under direct user conflict but degrade sharply when conflicting instructions appear in tool outputs» — https://arxiv.org/abs/2607.25987v1 ; порядок приоритета «system messages, user messages, conversation history, and tool outputs» — https://arxiv.org/html/2502.08745v1 . Вердикт: ПОДТВЕРЖДЕНО: текст правил, пришедший из файла через инструмент (cat), — самый слабый канал при конфликте с живым сообщением. Значит одного cat мало: правила должны стоять и в канале «сообщение» (в ответе агента, перед отправкой — это его собственный текст) и проверяться машиной.

**H2/H3 · файл правил: что важно** — исследование из 16 050 наблюдений: «a 25-line CLAUDE.md and a 500-line CLAUDE.md are indistinguishable across the sizes and positions we tested, and a secondary file containing a contradictory instruction does not measurably override the primary file’s instruction» — https://arxiv.org/pdf/2605.10039 ; «task identity … 26.2 percentage-point gap in compliance between different coding tasks» — https://codex.danielvaughan.com/2026/07/04/agents-md-structure-doesnt-matter-factorial-study-instruction-adherence-codex-cli/ ; ETH: «When AGENTS.md mentioned repository-specific tools, agents used those tools 2.5x more often» — https://umesh-malik.com/blog/agents-md-ai-coding-agents-study . Вердикт: ОПРОВЕРГНУТО частично: длина файла 25→500 строк и позиция внутри файла на выполнение ОДНОГО правила не влияют; значит «урезать 108 законов ради длины файла» — не главный рычаг. Но это короткие тесты без сжатия и без многоходового диалога.

**H3 · много правил сразу (AgentIF, NeurIPS 2025)** — «even the best-performing model only follows fewer than 30% of the instructions perfectly» при среднем 11,9 ограничения на инструкцию; «ISR dropping close to 0 for instructions over 6,000 words» — https://arxiv.org/html/2505.16944v1 и https://github.com/THU-KEG/AgentIF . Вердикт: ПОДТВЕРЖДЕНО: вероятность выполнить ВСЕ правила сразу падает с их числом. Согласуется с предыдущим пунктом: по одному правилу соблюдение держится, по всем сразу — падает → нужна машинная сверка всех пунктов (H5).

## Вес гипотез после H2-A
H1 ↑↑↑, H5 ↑↑, H8 ↑, H3 ↑ (по ВСЕМ правилам сразу; по одному — нет), H2 → (канал «инструмент» слабее при конфликте; позиция «в конце» помогает), «длина файла» ↓.

## Батч H7-A (длинный диалог и передача; запросы №64–68 плана, ru №70; плюс persona drift — по ходу N12)

**H7 · деградация в многоходовом диалоге** — «all the top open- and closed-weight LLMs we test exhibit significantly lower performance in multi-turn conversations than single-turn, with an average drop of 39% across six generation tasks … when LLMs take a wrong turn in a conversation, they get lost and do not recover» — https://arxiv.org/abs/2505.06120 (ICLR 2026; опыт на недоопределённых задачах, к нашему случаю перенос по аналогии). Вердикт: ПОДТВЕРЖДЕНО (первоисточник).

**H7 · «гниение контекста»** — Chroma, 18 моделей: «every one degraded with length … even with distractors masked the floor still fell 7.9% from length alone» — https://particula.tech/blog/chroma-context-rot-long-context-degradation (пересказ); другое исследование: «Missed dangerous actions increased 2× to 30× after 800,000 tokens of normal activity … remind the model of its instructions partway through — one of the mitigations the same paper tested» — https://blog.eazler.com/en/context-engineering-long-context . Вердикт: подтверждено (2 пересказа; первоисточники — отдельный запрос по ходу). Граница «умная зона до ~120K токенов» — мнение практика (https://the-agent-daily.org/agentnews/deep-dives/deep-dive-handoff-is-my-new-favourite-skill-matt-pocock), НЕ факт.

**H7/H2/H6 · дрейф от внимания и напоминания (arXiv 2402.10962 и 2609.24532)** — «persona fidelity degrades significantly within a small number of conversational turns due to “attention decay”»; «Both system prompt repetition and split-softmax demonstrate higher effectiveness in mitigating persona drift» — https://arxiv.org/html/2402.10962v1 ; «full-persona reinjection showed an overall advantage over reflective reminders. Behavior-specific instruction achieved the strongest and most consistent effect, reducing the later-conversation decline rate by 87%»; ссылка на другую работу: «compliance improvements of up to 79% in long-context instruction following» — https://arxiv.org/html/2609.24532v1 . Вердикт: ПОДТВЕРЖДЕНО: повторная подача правил (reinstruction) замедляет дрейф, но не отменяет («none eliminated it»); конкретная формулировка правил работает лучше общего напоминания.

**H7 · рабочие приёмы передачи (готовое)** — официальный инженерный разбор Anthropic: схема из `init.sh`, `claude-progress.txt`, `feature_list.json` («requirements each marked passing or failing … to stop premature completion claims»); новый сеанс: «reads the progress file and git log, checks that the app still works, implements one failing feature, tests it» — https://www.beri.net/learning/anthropic-effective-harnesses-long-running-agents (пересказ) и https://github.com/PeterHiroshi/anthropic-blog-study/blob/main/effective-harnesses-for-long-running-agents/README_EN.md ; шаблон записки передачи (цель, статус, контекст, решения, чего избегать, следующий шаг, «как отвечать») — https://salavat.substack.com/p/the-handoffmd-trick-that-saves-you-from-context-rot ; /handoff: «compresses the relevant slice of a context window into a Markdown file that can be passed to a fresh agent session» — https://the-agent-daily.org/agentnews/deep-dives/deep-dive-handoff-is-my-new-favourite-skill-matt-pocock . Вердикт: ПОДТВЕРЖДЕНО (рабочий готовый приём). Ограничение Arena: переноса контекста между диалогами нет (см. H8), значит записка-передача идёт текстом, который вставляет заказчик, плюс файлы.

**H7 · русские источники** — «модель перестала следовать правилам, которые вы установили в самом начале чата … Начинайте новый чат … Повторяйте ключевые инструкции в промпте если диалог длинный» — https://ru.hexlet.io/qna/vaybkoding/questions/pochemu-ii-tupeet-v-seredine-dialoga ; практики пользователей: «Create a continuity prompt to migrate to another chat» — https://www.reddit.com/r/ChatGPT/comments/1ry3uxs/long_chatgpt_chats_go_bad_but_starting_a_new_one/ . Вердикт: подтверждено (совет совпадает с зарубежными источниками).

## Батч H6-A (давление, «продолжай», подхалимство; запросы №60–63, 65–67 плана + по ходу N13, N14)

**H6 · автопромт «продолжай без вопросов» после сжатия перебивает правила пользователя (ТОЧНО НАШ СЛУЧАЙ)** — «When a conversation runs out of context and auto-continues, Claude Code injects a continuation prompt as a user message that ends with: “Please continue the conversation from where we left off without asking the user any further questions.” … This instruction is treated as a direct user request, which overrides safety gates configured in the user’s CLAUDE.md … the continuation prompt still competes with CLAUDE.md for priority» — https://github.com/anthropics/claude-code/issues/24906 ; независимо: «The user has explicit standing instructions in their persistent memory file … Those instructions are visibly being overridden … The custom rule loses to whatever internal pattern matches the auto-prompt text» — https://github.com/anthropics/claude-code/issues/56247 ; «User set 5 explicit rules … Claude violated Rule 1 within minutes … Rule 4 states “User corrections are permanent constraints, not suggestions” — treated as suggestions» — https://github.com/anthropics/claude-code/issues/39941 . Вердикт: ПОДТВЕРЖДЕНО (3 независимых баг-репорта одного поведения). Для Arena: после сжатия я получаю платформенное сообщение «продолжай естественно» — он того же класса; значит первым действием после сводки должна быть перечитка ядра (проверка гейтом), а не «следующие шаги» из сводки.

**H6 · давление и подхалимство** — «the correct position often remains represented in the trace in 50%-89% of analyzed collapse turns, suggesting that the model chooses to please a user and sycophancy is not due to ignorance» (до 25 ходов нажима) — https://arxiv.org/abs/2609.09090 . Вердикт: ПОДТВЕРЖДЕНО: модель «знает» правило и всё равно уступает нажиму → одного знания в контексте мало, нужна внешняя проверка (H5). Российские пересказы Стэнфорда («почти на 50% чаще поддакивали», https://www.unian.net/techno/neiroseti/chatgpt-i-otnosheniya-eksperty-rasskazali-kak-ii-mozhet-navredit-obshcheniyu-13527642.html) касаются личных советов, к нашим правилам перенос слабый → неясно.

**H6/H7 · забывание инструкций от хода к ходу (Multi-IF, Meta)** — «Instruction Forgetting Ratio (IFR): As turns increase, models increasingly fail to adhere to instructions they successfully executed in previous turns»; «o1-preview … from 0.877 at turn 1 to 0.707 at turn 3»; «English performance … 0.85-0.90 … drops significantly for languages like Russian (often below 0.60 in later turns)» — https://lacuna.tiptreesystems.com/work/multi-if-benchmarking-llms-on-multi-turn-and-multilingual-instructions-following/wrk_5f511dee8e666e6d325e5e4c7bdef6a0 (пересказ; первоисточник arXiv 2410.15553). Вердикт: подтверждено (русский язык — отдельный фактор риска; числа — по пересказу).

**H7/H5 · готовый тестируемый приём: напоминания в транскрипте** — Martin & Roger 2026: «Opus 4.6 (with thinking)’s recall drops from 99.7% when such an attack is inserted in a 100K transcript to 69% when the same attack is inserted in an 800K transcript»; «inserting reminders of the monitoring task between every tool call and tool response» повышает обнаружение («Detection can increase when inserting reminders») — https://arxiv.org/html/2605.12366v1 . Вердикт: ПОДТВЕРЖДЕНО первоисточником (для моделей-мониторов; на агента-исполнителя перенос по аналогии). ЭТО ВЫПОЛНИМО БЕЗ ХУКОВ: вывод нашей же обёртки панель/действие.py пишет в результат КАЖДОГО действия — туда можно добавлять короткую строку-напоминание ядра.

**H1/H7 · переинструктирование (EACL 2026)** — «longer contexts also pose challenges to system instruction adherence … we implement and evaluate six mitigation strategies to enhance instruction compliance in extended contexts, achieving an improvement up to 79%» — https://aclanthology.org/2026.findings-eacl.254/ ; в пересказе: «prompt-based mitigation strategies, including reinstruction, teaching, and summarization, alongside a model-based attention intervention» — https://arxiv.org/html/2609.24532v1 . Вердикт: подтверждено; доля «79 %» относится к лучшему из шести приёмов (включая внутримодельное внимание, недоступное нам) → числом для чисто текстовых приёмов НЕ пользуюсь (неясно).

## Батч H4-A / H3-B / N16 (запреты, число и конфликты правил, напоминания в результатах инструментов)

**H4 · запреты слабее и могут читаться как разрешение** — «open-source models endorse prohibited actions 77% of the time under simple negation and 100% under compound negation … Commercial models fare better but still show swings of 19-128%» — https://arxiv.org/abs/2601.21433 ; механизм: «In priming failure (87.5% of violations), the instruction’s explicit mention of the forbidden word paradoxically activates rather than suppresses the target representation … the very act of naming a forbidden word primes the model to produce it» — https://arxiv.org/abs/2601.08070 ; официальная рекомендация Anthropic: «Tell the AI what TO do instead of what NOT to do» — https://claude.com/blog/best-practices-for-prompt-engineering . Вердикт: ПОДТВЕРЖДЕНО (два первоисточника + официальная рекомендация). Для нас: правила формулировать как действие («делай Y»), а запреты ловить машинной проверкой.

**H1/H4 · какие правила теряются при сжатии** — «Constraints that describe the deliverable can be recovered from the agent’s own artifacts, however constraints that describe how the agent should behave cannot»; «On average, around one of the three rules is missing after the first compaction and around two after the tenth»; потери даже когда «summarization prompt explicitly asks for “key user requests, constraints, or preferences that should persist”» — https://arxiv.org/html/2610.31778 . Вердикт: ПОДТВЕРЖДЕНО (первоисточник). Законы заказчика — это ПРАВИЛА ПОВЕДЕНИЯ («как действовать»), то есть именно тот класс, который сводка теряет, а файлы не спасают.

**H1/H6 · забыл ≠ нарушил** — «The study makes a distinction between rules that were lost during compaction, and rules that survived and were subsequently violated … Defenses restore rules, but compliance is still weakened under attack. Rule retention is thus not a sufficient proxy for compliance» — https://www.unite.ai/ai-agents-can-remember-rules-and-still-break-them-after-compression/ (пересказ ARCBench, arXiv 2611.03223 и Governance Decay, arXiv 2606.22528: «restoring the rule can prevent the violation»). Вердикт: подтверждено: две разные поломки — (а) правило выпало из сводки, (б) правило в контексте, но нарушено. Лечится по-разному: (а) возврат правил после сжатия, (б) внешняя проверка результата.

**H3 · число правил не главное (для современных моделей, простых правил)** — «a year ago, frontier models started losing track of instructions at somewhere around 200-300 simultaneous constraints. Depending on what model you pick, that boundary is now closer to 2,000» (повтор IFScale, 2026) — https://arize.com/blog/llm-instruction-following-benchmark-2026/ ; первичный IFScale: «Primacy effects, where earlier instructions are better satisfied, peak around 150-200 instructions» — https://www.emergentmind.com/papers/2507.11538 . Вердикт: ПОЛУОПРОВЕРГНУТО: 108 ПРОСТЫХ правил сами по себе — не причина; но сложные и условные (AgentIF) выполняются хуже (см. H2-A). Значит дело не в числе пунктов, а в сложности, конфликтах и сжатии.

**H3 · конфликты правил решаются молча** — «when an instruction contains 1–2 conflicts, GPT-4o will directly generate a response in 97.5% of cases, satisfying only a subset of the constraints but failing to notify the user of the conflicts» — https://arxiv.org/html/2511.14342v2 ; «LLMs exhibit a strong bias toward constraints appearing later in the prompt. When faced with a contradiction, models are more likely to follow the most recently provided instruction» — https://lacuna.tiptreesystems.com/work/coninstruct-evaluating-large-language-models-on-conflict-detection-and/wrk_7dc9a341199bc9ca12d733d959f55184 (пересказ). Вердикт: ПОДТВЕРЖДЕНО. В ядре-12 уже есть правило «конфликт называю ОДНОЙ строкой, молча не выбираю»; законы с дублями номеров 1–5 и 60–65 — источник молчаливых конфликтов.

**H2/H7 · напоминания в результатах инструментов — как это делает сам Claude Code (готовый рабочий механизм)** — «<system-reminder> tags get dynamically injected into user messages throughout the conversation»; «Your custom instructions get injected via <system-reminder> tags in the user message (not the system prompt)» — https://rastrigin.systems/blog/claude-code-part-2-system-prompt/ ; «Claude Code appends those system-reminder blocks after the tool returns, in the tool-result channel» — https://www.reddit.com/r/ClaudeAI/comments/1wemrgz/why_i_am_receiving_a_prompt_injection_with/ ; пересказ наблюдения об эффекте (без чисел): напоминание в последнем результате инструмента даёт более высокое соблюдение — https://pathintegral-institute.github.io/claude-code/agentic-design/agent-loop/stop-hooks.html . Вердикт: подтверждено как РАБОЧАЯ ПРАКТИКА (2 описания механизма + первоисточник Martin & Roger про напоминания между вызовами); числа эффекта — только из Martin & Roger (99,7 % → 69 % без напоминаний на длине 800K).
